# Localization (language versions)

Every component ships its texts in the **predefined cultures: `cs-CZ`, `de-DE`, `es-ES`, `sk-SK`** (neutral = English). `es-MX` files exist in some libraries but are not required - do not create or fill them unless asked.

Translations are written by Claude; list them in the PR description so a native speaker can review.

## Where texts live

| Text source | Neutral file (who writes it) | Culture files (who writes them) |
|---|---|---|
| PLC: `'<#Text#>'` in code, `{attribute addProperty Name "<#Text#>"}` on declarations | `<Lib>Connector/Properties/Localizations.resx` - **generated by the Vortex compiler** on build | `Localizations.<culture>.resx` - by hand |
| WPF: `{x:Static p:strings.Key}` in XAML | `<Lib>.Wpf/Properties/strings.resx` - by hand | `strings.<culture>.resx` - by hand (casing varies, e.g. `strings.sk-Sk.resx`; keep the existing name) |

`Localizations.Designer.cs` is not used for PLC text lookup; it may stay stale. `strings.Designer.cs` **is** used by `x:Static` - every WPF key needs its property there.

## Key rule (PLC texts)

Key = `_` + the literal `<#Text#>` with every non-alphanumeric character replaced by `_`:

| PLC literal | Key | Value |
|---|---|---|
| `<#Stop program started.#>` | `___Stop_program_started___` | `Stop program started.` |
| `<#Waiting for signal: #>` | `___Waiting_for_signal____` | `Waiting for signal: ` |
| `<# is OFF#>` | `____is_OFF__` | ` is OFF` |
| `<#Emergency stop active#>` | `___Emergency_stop_active__` | `Emergency stop active` |

- Spaces and punctuation inside `<#…#>` change both key and value: `<#Waiting for signal#>` and `<#Waiting for signal: #>` are two different keys.
- Keep the neutral value's leading/trailing spaces in every translation - fragments are concatenated (`'<#Waiting for signal: #>'` + symbol + `'<# is OFF#>'`).

## Writing rules

- Every operator-visible PLC text goes in `<#…#>`; symbols (`_varInfo.Symbol`), numbers and `|[[0]Property]|` placeholders stay outside.
- Prefer one whole sentence per key over concatenated fragments when the word order differs between languages.
- Do not translate the vendor's signal / interface names (as written in the vendor manual, e.g. `ProgramActive`, `IN`, `OUT`); a translation equal to the English value is fine for those.
- Reuse the terminology already in the repo's culture files (grep the culture resx of the same library, then of the other vendor libraries, for the English phrase first). Existing terminology:

  | English | cs-CZ | de-DE | es-ES | sk-SK |
  |---|---|---|---|---|
  | Waiting for signal | Čekání na signál | Warten auf das Signal | Esperando señal | Čakanie na signál |
  | Stop program started. | Zastavení programu spuštěno. | Programm anhalten gestartet. | Detener programa iniciado. | Zastavenie programu spustené. |
  | Local emergency stop active | Aktivní lokální nouzové zastavení | Lokaler Not-Halt aktiv | Parada de emergencia local activa | Aktívne lokálne núdzové zastavenie |

- Translate the meaning, not a typo: if the English source is wrong (e.g. `Start movements stared.` -> means "started"), fix the PLC literal or at least translate the intended meaning, and tell the user.

## Procedure

1. Write the PLC texts with `<#…#>`; build with Vortex so `Localizations.resx` gets the new keys. (If the build is not available, add the neutral keys by the key rule - the next Vortex build will keep them.)
2. Run the check:
   ```powershell
   & .\.claude\skills\tco-vendor-component\scripts\Test-TcoLocalization.ps1 -LibraryPath src\TcoTemplate
   ```
3. For every `MISSING` key add to each culture file, next to the related keys:
   ```xml
   <data name="___Stop_program_started___" xml:space="preserve">
     <value>Zastavenie programu spustené.</value>
   </data>
   ```
   Remove `STALE` keys only after confirming the PLC text was really removed/renamed (then translate the new key).
4. WPF texts: add the key to `strings.resx` **and** every `strings.<culture>.resx`, then add the property to `strings.Designer.cs` (regenerate in Visual Studio - "Run Custom Tool" - or copy an existing property pattern).
5. Re-run the check until it reports `Errors: 0`. Review the `SAME` warnings: acceptable for signal names, otherwise translate.
6. Build the connector/Wpf project and check the satellite assemblies exist: `bin\Debug\net48\{cs-CZ,de-DE,es-ES,sk-SK}\<Assembly>.resources.dll`.

## File hygiene

- resx files are UTF-8 (with BOM) and CRLF - keep it; diacritics must survive. The scaffold script writes with `Set-Content` (ANSI on PowerShell 5.1), so check scaffolded resx files.
- Edit by inserting `<data>` elements; do not reorder or reformat existing entries (keeps diffs reviewable).
